# Experimental Lake Simcoe wind response

This directory contains a new, unvalidated **depth-averaged barotropic wind-response calculation**, not retrieved Lake Simcoe current observations or an operational forecast. It solves a restricted physical problem with documented real inputs. It does not recover actual surface circulation, and it is not an October climatology.

The mean window is **12 October 2026 00:00 UTC through 17 October 2026 12:00 UTC**. East and north velocity components are integrated separately. Mean speed is a separate quantity and never used to invent a direction.

## Reproduce from the frozen inputs

Run these commands from this repository's `model/simcoe` directory. The included [grid.npz](grid.npz) and [wind.json](wind.json) are the exact numerical inputs used for the retained run. The solver needs only Python and NumPy; it makes no network requests. With NumPy already installed, the numerical checks and solver run work offline.

```powershell
python -m pip install "numpy>=2.2,<2.4"
python test_solver.py
python solve.py --backend numpy --start 2026-10-01T05:00:00Z --output reproduced-longer-spinup
```

The last command reproduces the preferred start, forcing, grid, step and mean window. It writes `reproduced-longer-spinup.json`, `reproduced-longer-spinup-diagnostics.json` and `reproduced-longer-spinup-fields.npz` here. Floating-point results can depend on numerical-library versions and the backend. Diagnostics include wall-clock duration, so their bytes are not expected to match the retained report. The shipped [longer-spinup.json](longer-spinup.json) remains the original preferred field.

For a short run that exercises the actual frozen inputs before running the full calculation:

```powershell
python solve.py --backend numpy --start 2026-10-01T05:00:00Z --mean-start 2026-10-01T06:00:00Z --end 2026-10-01T07:00:00Z --output smoke
```

For the optional accelerated backend, install the full [requirements.txt](requirements.txt), then run `python test_solver.py --numba` and substitute `--backend numba` in the solver commands. NumPy remains the reference backend. Full requirements also supply SciPy, Matplotlib and Requests for regenerating bathymetry; Node is needed only for refreshing the wind inputs.

### Optional input regeneration

Regeneration requires network access and may retrieve changed upstream data. The larger original contour-response cache and raw API response are omitted from this repository. `prepare_grid.py` creates an `inputs/` cache when run, and reuses those local responses on subsequent runs. The frozen grid itself is sufficient for offline model reproduction.

From `model/simcoe`:

```powershell
python -m pip install -r requirements.txt
python prepare_grid.py --geography ../../src/geography.json
node fetch-wind.mjs
```

Or, from the repository root, use `python model/simcoe/prepare_grid.py --geography src/geography.json`. The default also detects the included [src/geography.json](../../src/geography.json); the original workspace layout remains supported. These commands overwrite the local grid or wind inputs. Run them in a separate checkout or keep the frozen copies if reproducing the retained run. `fetch-wind.mjs` retrieves hourly observations for October 2026 and records their metadata and flags. A later fetch may return a longer or revised record. Compare hashes before assuming it is the retained input.

The package includes source, frozen numerical inputs, the preferred mean field, manifests and diagnostic/check reports. Full-resolution intermediate run arrays and sensitivity-run arrays are regenerated by the commands below. No generated velocities are written into the map automatically.

## Physical problem

With undisturbed positive water depth `H`, free surface anomaly `eta`, and horizontal depth-mean velocity `(u,v)`, the continuous equations represented by the scheme are:

```
eta_t = -div(H [u,v])
u_t - f v = -g eta_x + tau_x/(rho_water H) - C_bottom |velocity| u/H
v_t + f u = -g eta_y + tau_y/(rho_water H) - C_bottom |velocity| v/H
tau = rho_air C_air |wind| wind
```

The momentum equations omit advective and density/thermal terms. The Coriolis parameter is constant at 44.45°N. The free-surface pressure gradient is generated by water moving against the actual bathymetry and closed shoreline. There is no arbitrary wind-to-current fraction or shoreline-following vector field.

The scheme uses an Arakawa C grid, finite-volume transport divergence, paired pressure gradient, and a corner `f/H` transport interpolation whose discrete Coriolis work cancels exactly. It advances all variables with third-order SSP Runge-Kutta. There is no imposed horizontal viscosity; this time integration damps high-frequency grid-scale modes. The default step is 10 seconds, constrained by a conservative bound on the linear gravity-wave frequency. Quadratic bottom drag and wind stress are explicit.

The air-water drag coefficient is 0.0013; bottom drag is 0.0025; water density 1000 kg/m³, air density 1.225 kg/m³. These constants are assumptions, not fitted Simcoe parameters. Sensitivity to drag and spinup is examined separately. Every wet/dry face is impermeable. **Atherley Narrows is closed**, with no tributary inflows or outlet throughflow.

## Inputs and provenance

- **Official Ontario LIO Bathymetry Line:** [service metadata](https://ws.lioservices.lrc.gov.on.ca/arcgis2/rest/services/LIO_OPEN_DATA/LIO_Open01/MapServer/30). The query selects actual contour features over the lake, then clips sample vertices to the exact Simcoe water polygon. `DEPTH` is negative metres and is negated to positive water depth. The [official data dictionary](https://www.publicdocs.mnr.gov.on.ca/mirb/Bathymetry,%20Line%20-%20Data%20Description.pdf) defines depth downward from the surface, in metres. The source horizontal CRS is NAD83; the query returns WGS84. The [Bathymetry Index](https://ws.lioservices.lrc.gov.on.ca/arcgis2/rest/services/LIO_OPEN_DATA/LIO_Open01/MapServer/31) identifies Lake Simcoe as `17-6327-49193` with a historic 1957 survey; some selected nearshore features are later. Individual contour records do not specify a consistent absolute vertical reference. This calculation uses depth below the survey water surface, not a claimed CGVD/CD elevation. Licence: **Open Government Licence – Ontario**. Original responses were cached during the retained development run. The cache is not included here; regeneration creates a new local `inputs/` cache.
- **Shoreline:** the existing project's OpenStreetMap/OpenFreeMap water union, including its island holes; ODbL 1.0. The exact source file SHA256 is retained in `grid-manifest.json`. Cell centres determine wet status. The 500 m grid cannot resolve every small island or channel. Depth is linearly interpolated from contour vertices thinned to 150 m and zero-depth shoreline/island vertices; coastal wet depth is floored at 1 m. These are explicit grid assumptions, not extra depth measurements.
- **Wind:** ECCC National Climate Archive hourly observations, Barrie-Oro station 6117700, retrieved through the [climate-hourly API](https://api.weather.gc.ca/collections/climate-hourly/items?f=json&limit=1000&CLIMATE_IDENTIFIER=6117700&LOCAL_YEAR=2026&LOCAL_MONTH=10). Speeds convert km/h to m/s; meteorological directions convert from tens of degrees true *from* to vector direction *toward*. The single land station is applied uniformly with no over-water correction. Nominal 10 m height is assumed from a standard station convention, not independently verified for this station. The observations are samples at hourly timestamps, not proven hourly mean winds. UTC timestamps are used directly; local timestamps are fixed EST, not daylight-saving time. The original source metadata, flags, retrieval date and exact conversion are retained in `wind.json` and `fetch-wind.mjs`. Licence: **Open Government Licence – Canada**.

## What the numerical checks establish

`test_solver.py` checks exact rest preservation; finite-volume volume conservation; zero work by discrete pressure+Coriolis; impermeable walls; drag energy dissipation; correct Northern Hemisphere Coriolis sign; positive downwind water setup; and timestep consistency on a synthetic basin.

Those checks establish properties of the numerical implementation. They **do not establish accuracy against actual Lake Simcoe currents**. The real-input run retains volume, energy, velocity and water-surface diagnostics throughout its simulation. Parameter/spinup tests measure dependence on assumptions rather than validate any resulting field.

## Retained run and sensitivity results

The preferred `longer-spinup.json` starts at rest on **1 October 2026 05:00 UTC**, then uses **259 hours** of observed wind before the mean window. The frozen 500 m grid has 2,873 wet cells, an area of 718.25 km² and interpolated volume of 10.884 km³. Its mean-vector speed has a median of 0.00735 m/s and maximum of 0.03803 m/s. Those numbers describe the experimental calculation, not measured water velocities. The maximum mean speed, 0.09601 m/s, is larger because reversing motion cancels in the mean vector.

The preferred run has 140,760 steps of 10 seconds. Its peak `abs(eta/H)` is 0.0611 and its minimum total wet depth is 0.9595 m, so no cell becomes dry in the linearized calculation. The closed-basin volume anomaly remains at floating-point roundoff. During development, a clean rebuild from the retained contour-response cache reproduced every frozen grid array exactly; [grid-rebuild-check.json](grid-rebuild-check.json) retains that check report. The response cache is omitted from this public package, so this historical check is separate from a fresh upstream download.

`sensitivity.json` records these comparisons of the weekly mean vector field:

| Change from preferred run | Vector RMS difference | Relative L2 difference | Component correlation |
| --- | ---: | ---: | ---: |
| Only 48 hours of initial history | 0.00494 m/s | 47.5% | 0.882 |
| 5-second timestep | 1.63 × 10⁻¹⁰ m/s | 1.57 × 10⁻⁸ | 1.000 |
| Bottom drag 0.0015 | 0.00332 m/s | 31.9% | 0.984 |
| Bottom drag 0.004 | 0.00238 m/s | 22.9% | 0.988 |
| 600 m grid, common interior only | 0.00270 m/s | 29.3% | 0.956 |

The 600 m comparison uses 2,112 interior cells and excludes shoreline geometry differences; it does not establish spatial convergence. The strong history dependence is why the longer history is preferred, and also why an unknown initial state remains a real limitation. The drag and grid comparisons show that local amplitudes depend on assumptions. These differences are **not confidence intervals**. Uncertainty from omitted thermal circulation and the single land wind station is not quantified by these tests.

To regenerate the full arrays needed by `compare_runs.py`, first create both baseline runs with these exact output names. ```

[source-hashes.json](source-hashes.json) hashes every delivered file other than itself under `files`. Its `originalRunManifest` retains the original development manifest verbatim as a JSON object, including the original README hash; that historical README hash is not a claim about this adapted public README. Solver code, preparation code, frozen grid/wind, preferred field and retained numerical reports are copied without changes. The wind source metadata was clarified during development without changing any numerical sample; the final output retains the matching final metadata and SHA256. Hashes establish file identity, not scientific validation.

## Why this does not replace a calibrated model

The [WSP Georgina Island coastal report (November 2024)](https://cdn.prod.website-files.com/64e5071b798e46ba8cbf81d3/674f66d12ef54c35a2d70f06_Coastal_Eng_Report_Final_20241125.pdf) documents a whole-lake Delft3D 2D depth-averaged mesh, with velocity calibration/validation against an October–November 2022 ADCP near the shallow Georgina crossing. That result is evidence that a barotropic shallow-site model can be useful, not validation of this solver. Its shallow-site reasoning does not establish that depth average represents the deep lake's surface currents. Its native numerical model and current outputs have not been recovered here.

The [Flood 2020 Lake Simcoe study](https://aslopubs.onlinelibrary.wiley.com/doi/10.1002/lno.11292) documents thermal/internal-wave circulation in Kempenfelt Bay, including 2014–2016 velocity and temperature observations. Those mechanisms are omitted here. Real surface velocity can differ substantially in direction and magnitude from this model's depth average. Other omissions include spatial atmospheric variation, wind sheltering, atmospheric pressure gradients, waves/Stokes drift, variable surface heating, tributary flow and Atherley exchange. Historical interpolated bathymetry and 500 m coast representation further limit local interpretation.

If displayed beside official model products, this field must remain clearly identified **in the visible map/film** as an experimental, unvalidated depth-averaged wind response. Do not label it observed, validated, real-time surface currents, or a multi-year seasonal average.
